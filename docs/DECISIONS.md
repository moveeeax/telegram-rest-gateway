# Журнал решений (ADR-lite)

Фиксирует принятые решения по проекту. Источник истины при расхождениях с прозой
в `TZ_TDLib_Drogon_REST.md` и `docs/SPEC_ELABORATION.md`.

## Базовые решения (v2.0, продукт)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Кол-во аккаунтов | Single-account |
| 2 | Интерфейс TDLib | Нативный C++ (`td::ClientManager`) |
| 3 | Scope MVP | Сообщения + чаты + файлы |
| 4 | Платформа | Linux **amd64 + arm64**, Docker |
| 5 | API auth | Статический Bearer-токен |
| 6 | Доставка апдейтов | Только WebSocket |
| 7 | Файлы | Стриминг через сервис |
| 8 | Хранение/логи | Шифрование БД TDLib, без логирования контента |

## Решения по вопросам архитектурного совета (v3.0)

| # | Вопрос | Решение | Статус |
|---|---|---|---|
| C1 | Семантика `sendMessage` | **202 Accepted + temporary_message_id, финал по WS** | ✔ принято |
| C2 | Формат 64-битных id в JSON | **Строки** (десятичный int64, `pattern '^-?[0-9]+$'`) | ✔ принято (рек. совета) |
| C3 | Гарантия доставки WS | at-most-once, добор через `getChatHistory` | ✔ дефолт (рек. совета) |
| C4 | Переполнение WS-буфера | disconnect (close 1013), порог `ws_max_pending_updates=1000` | ✔ дефолт (рек. совета) |
| C5 | Идемпотентность POST /messages | at-least-once; Idempotency-Key — post-MVP | ✔ дефолт (рек. совета) |
| C6 | Модель download | **202 + поллинг, затем стрим `newFileResponse`**; Range/206 — post-MVP | ✔ принято |
| C7 | Регистрация нового аккаунта / email-логин | MVP только существующие аккаунты; `wait_registration`/`wait_email*` → `409 AUTH_REQUIRED` | ✔ дефолт (рек. совета) |
| C8 | TLS-терминация и bind | За reverse-proxy с TLS; `listen_address=127.0.0.1`; отказ старта при небезопасном bind | ✔ дефолт (рек. совета) |
| C9 | Целевая архитектура MVP | **amd64 + arm64 сразу** (переопределяет рек. совета «только amd64»). Требует нативных arm64-раннеров | ✔ принято |
| C10 | Формат upload | **Сырой `application/octet-stream`** (стрим в temp-файл) | ✔ принято |
| C11 | Удалённая ревокация сессии | degraded-режим (не exit) | ✔ дефолт (рек. совета); подтвердить |
| C12 | Экспозиция метрик `/metrics` | отдельный `metrics_port=9091`, bind внутренняя сеть | ✔ дефолт (рек. совета); подтвердить |

## Следствия C9 (multi-arch с первого дня)

- CI собирает `linux/amd64` и `linux/arm64`, объединяет манифест (`docker buildx imagetools`).
- `Dockerfile.tdlib` / `tdlib-base` кэш — по одному на каждую арку.
- **Инфра-требование:** нативные arm64-раннеры в GitLab CI (кросс-компиляция TDLib
  проблематична из-за host-генератора TL; QEMU рискует OOM на `td_api.cpp`).
  → уточнить наличие раннеров у заказчика (открытый вопрос инфры).
- Раздел 11.4 приложения (`docs/SPEC_ELABORATION.md`) с рекомендацией «одна арка»
  **переопределён** этим решением.

## Открытые вопросы (не блокируют старт Stage 0–1)

- Числовые SLO (p99 latency, пиковый RSS, число параллельных download).
- Нужна ли авторизация на `metrics_port`.
- Политика readiness при `connectionStateWaitingForNetwork > 30с`.
- Тестовый Telegram-аккаунт на test DC + соответствие ToS — кто предоставляет (нужен для Stage 2).
- Комплаенс на базовые образы (`debian:12-slim`, `distroless/cc-debian12` по digest).

## Секреты, нужные до запуска (blocker перед Stage 2)

`api_id`, `api_hash`, `database_encryption_key` (32 байта, стабильный, внешний),
список Bearer-токенов — в формате `*_FILE` / secret manager.
